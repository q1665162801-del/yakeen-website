# Yakeen Website V2 — Engineering Design Spec

> Date: 2026-07-31
> Status: Approved (Alan authorized full discretion)
> Strategy: Full rewrite, Astro framework, zero-downtime cutover

## 1. Problem Statement

Current site: 78 static HTML files, no component reuse, no build system, no git, 632KB i18n JS runtime. Every nav change requires editing 78 files manually.

## 2. Solution: Astro Full Rewrite

### Tech Stack
- **Framework:** Astro (static-first, zero JS runtime)
- **Styling:** Tailwind CSS v4 + design tokens
- **i18n:** Astro built-in i18n routing (prefixDefaultLocale: false, EN at root, AR at /ar/)
- **Content:** Astro Content Collections (blog/FAQ as MDX, products as JSON+YAML)
- **Images:** Astro's built-in image optimization (auto WebP/AVIF + srcset)
- **Deploy:** Cloudflare Pages (same domain, zero-downtime switch)
- **CI/CD:** GitHub Actions (push to main → build → deploy)

### Architecture
```
src/
├── components/     # Header, Footer, ProductCard, etc. (write once, reuse everywhere)
├── layouts/        # BaseLayout, ProductLayout
├── content/        # Blog & FAQ as MDX collections
├── data/           # Product data (JSON), i18n strings (JSON), site config
├── pages/          # File-based routing
│   ├── index.astro          # EN homepage
│   ├── products/[slug].astro  # Dynamic product pages (1 template, 10 products)
│   ├── blog/[slug].astro      # Dynamic blog pages
│   └── ar/                    # Arabic mirror
├── styles/         # global.css + Tailwind
└── utils/          # Schema generators, i18n helpers
```

### Key Improvements
| Area | Before | After |
|------|--------|-------|
| Nav update | Edit 78 HTML files | Edit 1 Header.astro |
| i18n | 632KB JS runtime | Build-time JSON, 0 runtime |
| Product pages | 10 hardcoded HTML files | 1 template + 1 data file |
| Blog/FAQ | Hardcoded HTML | MDX content collections |
| Images | Manual WebP conversion | Build-time auto-optimization |
| Deploy | Manual wrangler command | git push → auto CI/CD |
| Version control | None | Git with full history |
| Code quality | No checks | ESLint + TypeScript |

### Migration Plan
1. Build new project in `yakeen-website-v2/` (old site stays live, untouched)
2. Migrate all content into component structure
3. Verify SEO parity (Schema, hreflang, sitemap, meta tags)
4. Test all pages + visual regression
5. Switch Cloudflare Pages project to new build
6. Zero downtime — old site serves until new one is ready

### SEO Preservation (Critical)
- All URLs remain identical (no redirects needed)
- All JSON-LD Schema preserved (Organization, Product, FAQPage, BreadcrumbList)
- hreflang tags preserved (EN/CN/AR/x-default)
- Canonical URLs preserved
- OG/Twitter Card tags preserved
- noscript fallback content preserved
- Sitemap auto-generated by @astrojs/sitemap

### Risk Mitigation
- Old site continues serving until new one is fully tested
- New site built in separate directory, deployed to separate Cloudflare preview
- Full QA checklist before cutover
- Instant rollback if issues found (switch Pages project back)
